# REE Tracker — Feature Register

Single source of truth for what the app can actually do today. Generated from a direct scan of
`ree-tracker/src/{features,pages}`, `ree-tracker-backend/src/{routes,engine,services}`, and
`ree-tracker-backend/src/sockets`. Maintained per the rule in [CLAUDE.md](CLAUDE.md) — updated on
every feature add, change, or removal, not on a schedule.

---

## App structure (2026-10 reorganization)

- [x] **Five destinations, phone-first** — **Today · Practice · Exams · Progress · Library**, one model (`layouts/navModel.js`) behind a phone bottom bar (`layouts/BottomBar.jsx`) and a desktop sidebar (`layouts/Sidebar.jsx`).
  - The active item is matched by whole first path segment, so the exam runners (`/simulator`, `/gauntlet/:n`, `/battle/:id`) light Exams; the old shell never highlighted the simulator.
  - The phone's hamburger drawer is gone. Its top bar (`layouts/PhoneHeader.jsx`) holds the focus timer (a sheet), connection status (to `/account#offline`) and an **account menu** (`layouts/AccountMenu.jsx`: Account · Admin for admins · Log out, which says how many unsynced answers a logout would discard).
  - The shell is an `AppShell` layout route, so navigation stays on screen while a page chunk loads. A new page opens at its top, or at the linked section.
  - The "Enter the Board Simulator?" confirm modal is gone; the same warning is a line above Start on the setup screen.
  - **Desktop Log out:** the sidebar has a Log out button beside the Account card (with the same unsynced-answers warning); it was only in the phone menu.
  - **One avatar** (`components/Avatar.jsx`) for the sidebar and the phone menu, falling back to the email's initial in both. **A rename shows at once:** Firebase updates the user in place, so the sidebar and menu kept the old name until a reload; `updateDisplayName` in AuthContext re-renders them.
  - **Connection badge:** in the collapsed sidebar the state was only a hover title; a screen reader now hears "Online"/"Offline" as it changes and can read the counts. The badge text is at least 12 px (it was 9–10 px) and plain: "3 waiting to sync", "300 saved for offline".
  - **Focus timer:** the floating timer sits just above the phone's bottom bar, home-indicator inset included (a fixed 88 px sat under it). Its settings edit a draft: minutes are kept to 1–120 (clearing a field set a 0-minute block), there's a Cancel, and Save restarts the timer only when a duration changed (`components/Pomodoro.jsx`, `utils/pomodoroLogic.js` `clampMinutes`).
  - **App update:** a new version shows a toast with **Reload** instead of a blocking `confirm()` that interrupted whatever the learner was doing (`main.jsx`).
  - **Loading screens:** only the boot screen's label is a live region, so the rotating tips are no longer read out every few seconds; a page chunk loading says "Loading…" (was "Loading module").
- [x] **Today** (`pages/Today.jsx`, was the Dashboard) — the home screen answers "what should I do now?": an exam countdown (Manila days, or a link to set the date), the streak, and the **Today card** (contents under Analytics & insights). "Set your exam date" and the target's "Change" are full touch targets; the next-step buttons sit full width under their text on a phone; "1 day to go" (was "1 days").
  - It used to be eleven stacked cards. Pass chance and the projected average appeared twice, today's target three times, and "Next best actions" overlapped "Today's prescription". The KPI strip, ability chart, forecast card, heatmap, confidence matrix and AI report moved to Progress; the mock ledger to Exams → Past sittings; the "Daily targets" panel became the Today card's per-subject bars.
  - The header's sync pill is gone (the shell's connection badge covers it), and the skeleton matches the new page (`TodaySkeleton`).
  - **Shared stats** (`hooks/useDashboardStats.js`): the reconciled aggregate Today and Progress both read, lifted from the Dashboard. The payload lives in `services/analyticsSync`, and both pages subscribe to it (`useSyncExternalStore`). Moving between them shows the last numbers at once instead of a skeleton, and the app-wide sync refresh reaches them. The Dashboard used to refetch on its own after every sync as well, doubling that request. The cached payload is keyed by account, so signing in as someone else never shows the previous account's numbers.
- [x] **Exams hub** (`pages/Exams.jsx`) — tabs Mock board · Gauntlet · Battles · Rankings · **Past sittings** in `?tab=` (`hooks/useTabParam.js`, which replaces history so Back leaves the page). Mock board lists the four formats (`features/exams/MockBoardTab.jsx`, from `features/board-simulator/profiles.js`), each opening `/simulator?profile=<id>` with that format chosen. Past sittings is the mock-board ledger that used to close the Dashboard. The Gauntlet, Battles and Rankings tabs are their own modules (`features/exams/{GauntletTab,BattlesTab,HostBattleModal,RankingsTab}.jsx`, each a lazy chunk), split out of the 700-line `pages/Arena.jsx`, which is deleted. The Gauntlet's ladder rules are pure and tested (`gauntletTierState.js`), and its cooldown is derived from a ticking clock instead of set from an effect. Battle formats take their names and icons from the mock-board profiles (`battleModes.js`). Section headings are h2 under the hub's h1; Arena's were h3. Rankings opens with **Your rank** (`features/exams/YourRankCard.jsx`, one `/leaderboard/me` request), which used to be a ring labelled "Global Matrix Ranking" in Profile. When you're in the list below, the card uses your place in it: `/me` and the list are separate requests that can straddle a snapshot rebuild, and once showed #2 above a list with you at #1. The list no longer numbers the server's leading "you are here" row as #1 when you're outside the first page.
- [x] **Progress** (`pages/Progress.jsx`) — one question per tab, in `?tab=`, each tab its own chunk (recharts loads only where a chart is drawn):
  - **Overview** — KPIs, the ability trend (θ) with its day/week/month range, the PRC-rule forecast card, and the **AI board report** (`features/progress/{OverviewTab,AiBoardReport}.jsx`).
  - **Topics** — the mastery heatmap (each tile starts a drill) and accuracy by subject.
  - **Weak spots** — the weak-spot and blind-spot drills, the cross-session blind spots and time sinks, and **Recommended fixes** (the prescription panel; its routing is `features/progress/prescriptionRouting.js`).
  - **Confidence** — the confidence matrix, the calibration curve, and accuracy at each confidence level.
  - **Habits** — the **study calendar**, study time over the last 14 days, and time per question by topic. "Minutes per day, last 14 days" shows all 14; the list's 12-row cap cut the two newest, today and yesterday, off an oldest-first list (`sections/shared.jsx` `BarList limit`).
  - **Syllabus** — the Read / Watched / Drilled checklist per TOS topic and board-weighted coverage (see Syllabus checklist).
  - **Study plan** — the planner.
  - These were spread over the Dashboard, Profile's "Comparative analytics" and "Deep analytics" (`features/analytics/AnalyticsDeepDive.jsx`, now split into `useDeepAnalytics.js` and `features/analytics/sections/*`), and the planner. Each section has an h2 heading under the page's h1 (they were h3, with emoji). **Dropped:** the deep dive's "Score history" tab (the same sittings as Exams → Past sittings) and the "Active Network Agents" online list.
  - `useDeepAnalytics` keeps each result per account for the session: a tab shown again appears at once and refreshes in the background after two minutes. A failed fetch shows an error with Try again, never "no data".
- [x] **Account** (`pages/Account.jsx`, replaces Profile) — one scrolling page with anchored sections that other screens link to (`/account#offline`). **Jump links** to the nine sections sit under the header; on a phone "Sign-in & security" was a long scroll away with nothing saying it was there.
  - **Your name.**
  - **Exam plan** (`features/account/ExamPlanForm.jsx`): the **only** editor for the exam date and daily target (10–500), with days to go and the per-subject split. The date used to be editable in three places (Profile, Daily targets "Config", the planner), and the target only in Config. **The date can be cleared**: an empty date is saved as none (the store used to drop it, so a date once set could never be removed).
  - **Appearance** (the 13 themes).
  - **Notifications** (`NotificationSettings.jsx`). The one-time reminder offer after a first session is a card inside the results screen that ends it (Practice's summary, mock-board results, Gauntlet results), not a floating card over their last buttons. While a results screen hosts it, the floating copy hides; elsewhere it still floats (`components/NotificationOptIn.jsx`).

  - **Achievements:** milestones (`Milestones.jsx`, moved out of the analytics tab, with icons instead of emoji) and the readiness certificate. The certificate unlocks on the **real Board Readiness Index only**, says where it stands ("Readiness 52 of 70"), and offers Try again when the score can't load. It used to fall back to an ability-only (θ+3)/6 figure while loading or offline, so it could unlock and print on a number Today never showed (`features/profile/CredentialsTab.jsx`).
  - **Your data** (`DataSettings.jsx`): Delete all analytics, behind a confirm. It used to sit in the dashboard's Daily targets Config, next to Save.
    - The confirm says how many unsynced changes on this device it discards too.
    - Afterwards Today and Progress no longer paint the deleted numbers: the last dashboard payload and the service worker's cached analytics responses are dropped (`forgetDashboardStats`, `purgeApiCache`).
    - The exam date and daily target are kept (they are settings; the server keeps them, and the form used to come back blank).
    - **Removed: "Reset today's counts".** Today's counts are the answers recorded today, so the next sync put the server's numbers straight back; the button never did anything lasting.
  - **Sign-in & security** (`SecuritySettings.jsx`): **Send a reset email**, **Change password** (re-authenticates first; plain messages for a wrong password, a weak one or rate limits), Log out, and Delete account.
    - **Delete account asks for the password first** and re-authenticates before anything is deleted, then deletes the server data, then the sign-in. It used to delete the data first; when Firebase then demanded a recent sign-in, the learner was told to sign in again with nothing left to come back to. The button shows its progress, so a double tap can't send two deletions (`reauthenticate` in `contexts/AuthContext.jsx`).

  - **The login screen shows its messages.** The toast host was mounted only inside the signed-in app, so "a reset link is on its way" never appeared, and queued toasts popped up after signing in. One host now serves both (`App.jsx`). "Forgot password?" shows that it is sending.
  - **Plain sign-in errors.** The login screen showed Firebase's raw text ("Error (auth/invalid-credential).") It now says "That email and password don't match an account", "An account already uses that email", "You're offline", and so on. One mapping, `utils/authErrors.js`, serves the login screen and Account › Security.

## Exam & Practice Modes

- [x] **Practice** (`pages/Practice.jsx`, was Active Review) — per-question reveal MCQ and flashcard practice (`features/active-recall/{FlashcardMode,MCQMode,ReviewSetup,useReviewSession}.jsx`).
  - **Launched from elsewhere** (Today, Progress, a review), it says "Starting your session…" until the session opens; the setup form flashed up first, as if the tap had gone nowhere.
  - The **Flashcards** preset uses conceptual items only: a calculation as a flip card had a bare number on the back.
  - **AI questions on "All subjects"** pick one real subject and one of its topics per batch; they asked the model for subject "All", topic "General".
  - With no live syllabus loaded (a new device offline), the subject and topic lists fall back to the built-in syllabus instead of being empty.
  - The per-question clock is labelled "This question" and stops pulsing when it passes three minutes (it turns red).
  - The summary's three figures stack on a narrow phone. The mode guide marks Practice "You're here" instead of linking to the page it's on.
  - **Setup:** due reviews, then four one-tap presets: **Quick 20 · Weak spots · Flashcards · Bookmarks**. "Weak spots" is the one learner entry to the adaptive drill. It used to be offered three ways: that preset, a "Weak points" scope, and a "Smart drill" source that silently ignored the chosen subject.
  - **Custom session:** mode, focus, scope (**all subjects / one subject / one topic**), length, and source (**Question bank / My bookmarks / AI generated**). A preset's config left in the form (a drill, the due queue) shows and starts as a question-bank session over every subject (`features/active-recall/customView.js`).
  - **A fixed set** (`itemsPreset`): practises exactly the questions handed over — a past sitting's misses from its review — offline too, and "Practise again" repeats the set. The list never stays in the custom form's config.
  - **Bookmarks source:** practises up to 100 saved questions (`fetchBookmarks({ limit })`), filtered by subject under any stored spelling and topic, and shown as bookmarked. Bookmarks could be saved but never practised. Library › Bookmarks has a **Practise bookmarks** button.
  - **Session summary** (`features/active-recall/{buildSessionSummary.js,SessionSummary.jsx}`): when a session ends, the score, time and time per question; answers wrong while sure and right while unsure; accuracy by topic, worst first; up to ten missed questions with their answers (confident misses first). Next steps: **Practise again** (the same session, a drill's target included), **Drill** the weakest topic, **See your progress**, **Done**. Built from the recorded attempts before they are cleared; nothing is shown after a session with no answers. A session used to end on a toast and drop back to setup.
  - Plain messages replace "Encrypting and Syncing Telemetry", "Anomaly Reported" and "AI Core Offline".
  - One keypress records one answer: the option (1-4/A-D) and confidence (Q/W/E) hotkeys are owned by `QuestionCard` alone — the page used to bind them too, so both listeners fired and every keyboard answer was staged twice under two uuids the server could not dedupe (`pages/Practice.hotkeys.test.jsx`). Enter on a focused button is left to the button; the page also advanced, so the button's own click landed on the next question.
  - **End session asks first** once something has been answered ("You've answered 7 of 20…"), instead of ending on one tap.
  - **Leaving mid-session keeps the session.** Going to another tab or pressing Back used to drop the study-session record (study time) and leave the store's session open; the answers themselves were already queued. The record is now queued in the durable outbox and the session closed.
  - **Flagging follows the question.** A flag request that finished after the learner moved on flagged the next question instead.
- [x] **PRC board verdict** — one definition of pass/fail, shared by the results screen, exam history and the pass-rate KPI: a 70% general **weighted** average (Math 25 / ESAS 30 / EE 45) AND no rated subject below 50%, via `gradeBoardExam`. Subjects an exam never asked about stay unrated rather than counting as zero, and the remaining weights renormalise. Every caller used to judge the **raw** share correct as if it were the weighted average — they agree only when item counts sit in exact syllabus proportion, so a 90/60/64 sitting (71.3% raw, 69.3% weighted) passed. The results hero is now coloured by the verdict (it banded on old 70/60 score cut-offs) and shows the GWA it was judged on; Score History re-derives never-finalised sessions from their own attempts' per-subject split, so the subject floor applies there too. Previously five copies with two different thresholds, so a 55% mock showed FAILED on screen and CONDITIONAL PASS in history (`@ree/shared` `verdict`/`exam`, `services/examService.js`, `services/deepAnalyticsHelpers.js`, `features/board-simulator/{useSimulatorEngine,battleGrades,SimulatorDiagnostics}`)
- [x] **PRC exam format** — one constant for the board schedule, `PRC_EXAM_FORMAT` in `@ree/shared`: **Mathematics 100 items / 5h, ESAS 100 / 4h, EE 100 / 6h** (PRC's current schedule; Math was still 4h). The Simulator's PRC Standard sitting, its time display, the Gauntlet subject boards, battle hosting and every copy string derive from it (`PRC_TIMES`/`PRC_FORMAT_SUMMARY` in `config/examStandards.js`). Blended pools split items with one shared largest-remainder rule (`apportionItems`), so counts always sum to the total — the client turned a 10-item blend into 11. Unanswered items are recorded as LOW confidence and are never blind spots (they defaulted to HIGH, making every blank "confidently wrong"); answered-without-confidence is MED
- [x] **Server-side mock history** — every Board Simulator and battle sitting is **finalised on the server**: `POST /api/exams/sessions/:id/finalize` grades the session from its OWN recorded attempts (per-subject scores, the PRC weighted average, the verdict) and stores them — the client only describes the sitting. Sessions used to stay `IN_PROGRESS` forever, and the only per-subject record of a sitting was a device-local IndexedDB ledger, lost with a cleared browser and invisible on another device. The simulator finalises right after its telemetry lands, or queues the finalise behind the telemetry in the outbox (409 until the attempts arrive, then it runs); battles now record one session per player and finalise it server-side (they used to write session-less attempts). **Past sittings** (`components/MockBoardAnalytics.jsx`) asks the server on every visit, painting the last list meanwhile; it used to keep a module cache and never refetch, so a sitting just finished (the results screen sends you there) wasn't listed. A failed load says so with Try again instead of "No mock boards yet". Scores show the weighted average to one decimal (a 69.6 read "70%" beside Failed) and are coloured by the verdict; types use the format names ("Mixed paper", "Custom mock", `sittingKindLabel`); the trend is dated, not "Run 7", and its bars fit a phone; the tiles say "last 20"; every row has **Review**. The dashboard's mock history reads `GET /api/analytics/deep/mock-history` (cached by the service worker for cold starts, ownership-guarded), headlines the weighted average, and derives the numbers for sittings recorded before finalisation existed. "Remove" **hides** a sitting from history rather than deleting it — a delete cascades to the attempts and would rewrite every tally and mastery estimate the sitting fed. The old local ledger is emptied once the server copy loads, on sign-out and on account deletion (`services/examHistory.js`, `components/MockBoardAnalytics.jsx`, `services/simulationLedger.js`). The unused legacy `DELETE /api/exams/history/:id`, which hard-deleted a session and its attempts, is removed; hiding is the only way out of history.
- [x] **Sitting review** (`pages/SittingReview.jsx`, `/exams/sittings/:id`) — any finished mock board, full board, battle, placement test or Gauntlet run, item by item.
  - **Each item:** the question, your answer beside the key, the written solution and **Explain with AI** (the shared panel), its topic, time and confidence, and whether you marked it. It says when an answer wasn't recorded (sittings from before answers were stored) or was left blank.
  - **Filters:** All · Wrong · Blank · Marked · Slow (over the board pace for its subject) · Sure but wrong, each with its count, per subject. The navigator numbers items by their place in the sitting.
  - **Pacing** (`features/exams/{pacing.js,PacingPanel.jsx}`): per subject, the average time per item against the board's pace, how many were fast, on pace or slow, and the five slowest with a link to each.
  - **Go again on what you missed:** **Retake missed (timed)** runs exactly those items in the simulator at the board's pace for each item's subject (kind `retake` in Past sittings); **Practise missed** runs them in Practice, untimed, with answers as you go (`itemsPreset`). Both work offline once the review is open. The retake is checked against the signed-in account and its questions are never stored in the setup config or the draft.
  - **Answer sheet:** the navigator also opens as the PRC answer sheet, with your bubble shaded and the correct one ringed.
  - **Opened from** every Past sittings row (Review), the results screen (Review every item), the full board's result (Review all three sections), the Gauntlet result (Review every item) and the placement result (Review your answers, which the test's intro had promised and never shown).
  - States: still in progress (answers open once a sitting ends), still syncing (Try again), offline (Needs a connection), not found.
- [x] **Sitting review (API)** — `GET /api/analytics/deep/sittings/:id/review` returns one finished sitting item by item: the question, **the learner's answer**, the correct answer, the written solution, confidence, time and whether it was marked for review. It serves mock boards, full boards (all three sections, in board order), battles (in the battle's question order), placement tests (from their stored responses) and Gauntlet runs.
  - **Answers are stored now.** A `QuestionAttempt` kept only right/wrong, so no past sitting could show what was answered. Every attempt now stores the option picked (`selectedAnswer`; '' = left blank) and its position in the sitting (`itemIndex`). Sittings from before this show "not recorded" for the answer (additive migration `20261010000000_sitting_review_gauntlet_state`).
  - **Never mid-exam.** A sitting is reviewable only once it is closed: a mock finalised (or left open over a week), a battle completed by everyone, a placement test finished, a Gauntlet run graded. Otherwise it answers 409, so the endpoint can't be used to read the key during a full board or a live battle. A closed sitting whose answers are still in the outbox answers 409 "syncing".
  - Owner-scoped; under `/api/analytics` so the service worker's per-account cache can reopen a reviewed sitting offline (`services/sittingReview.js`, `tests/sittingReviewRoute.test.js`).
  - Items marked for review travel with the sitting: `POST /sessions/:id/finalize` accepts `markedQuestionIds` (a full board sends the union of its sections) and stores the union, so a replayed finalise never drops marks. A new sitting kind, `retake`, is accepted.
- [x] **Syllabus checklist** (Progress › Syllabus, and a line on Today) — the board's topic list as a checklist, adapted from the psychometrician tracker's Tracker and TOS Summary sheets.
  - **Per topic:** Read, Watched and Drilled ticks, the dates started and finished, a note, and "Drill this topic", which opens a smart drill on that topic.
  - **Drilled ticks itself** from the learner's answers: 20 in the topic, or 10 at Developing mastery or better.
    - It is computed when the list is read (`isAutoDrilled` in `@ree/shared`), never stored.
    - It uses the stored mastery, not the decayed one, so a tick never disappears after a few unpractised weeks.

## Adaptive Engine (backend, `ree-tracker-backend/src/engine/`)

- [x] **Item Response Theory (3PL)** — stateless per-item ability estimator, single unified θ + standard error per user, θ clamped to ±4 with an SE floor of 0.35 (`engine/irt.js`). **One item-parameter rule** (`itemParams`) serves the estimator, the CAT picker, calibration seeds and the θ backfill: an uncalibrated item is placed by its author rating mapped onto the θ scale (`authorB`: 1/2/3 → b −1/0/+1). Every consumer used to restate its own fallback and read `difficulty` raw as b — but authors and the AI write it on a 1/2/3 ordinal, so the typical "Core" item sat at b = 2 and θ drifted upward for everyone until calibration caught up. Missing-SE fallbacks are one `PRIOR_SE` = 1 (the population prior; four sites disagreed at 0.5/1/1/1.0), new users start there (`User.standardError` default 1.0, migration `20261002000000_user_prior_se_default`), and a purge resets SE too. `npm run audit:difficulty` reports the bank's actual difficulty distribution read-only before rollout (`engine/irt.js`, `scripts/auditDifficulty.js`, `tests/itemParams.test.js`)
- [x] **Bayesian Knowledge Tracing (BKT)** — per-topic P(mastery) driving the topic mastery heatmap, complementary to θ (`engine/bkt.js`). **Mastery decay**: BKT has no forgetting term, so a topic mastered early stayed "Mastered" however long it went untouched. `decayedMastery` decays the stored estimate toward pInit with time constant 21 d · (1 + ln(1 + n)) — ~3 weeks for a topic seen once, ~10 weeks behind fifty observations — from `UserTopicPerformance.lastPracticedAt` (new nullable column, forward-only, set by the rollup upsert and backfilled by `backfill:mastery`; migration `20261002010000_topic_last_practiced`). Display/priority only — the stored pMastery stays the pure evidence fold. The dashboard serves `masteryEffective` + `daysSincePractice`; the heatmap bands on the effective value and marks a topic "fading (Nd)" when time away has dropped it a band. Mastery bands (85/65/45) live once in `@ree/shared` (`MASTERY_BANDS`, `masteryBand`) instead of in the heatmap and the backfill separately (`services/masteryView.js`, `components/HeatmapChart.jsx`). `npm run backfill:mastery` rebuilds each learner's topic rows from their attempt history. Mastery is replayed through BKT; attempts, correct and time are counted by the live telemetry rule, so a correctly kept row is unchanged and a drifted one is corrected and reported. A missing topic key is created with its real counts. A row whose label no longer has attempts (relabelled away) is removed **only when history proves where its tally went**: answers were recorded under that label, they now count under another row, and together they cover the row's whole tally. Any other such row is left as is and reported with the reason: nothing was recorded under it (e.g. its questions were deleted), or it counts more than history holds. Each learner is rebuilt in one transaction under the same user lock telemetry takes. It used to create new keys with `correct: 0` and leave the old label's row behind (`scripts/backfillMastery.js`)
- [x] **Elo rating** — multi-player adapted rating for Arena leaderboards and Battle outcomes (`engine/elo.js`)
- [x] **Readiness score** — composite of topic coverage, accuracy, θ, consistency and blind spots, with the scoring rule extracted into a pure, unit-tested service (weights, θ normalisation derived from the estimator's own bounds, blind-spot definition and clamps) rather than inline in a route handler (`services/readinessService.js`, `readinessRoutes.js`)
- [x] **Forecasting model (v2-prc)** — the pass probability models the **PRC rule itself**: each subject's ability (per-subject `UserAbility`, or the global θ with the full prior uncertainty when a subject has no evidence) maps to an expected board score through the **test characteristic curve** of a 1,500-item random sample of the live bank (10-minute cached, tabulated on a θ grid), and 2,000 seeded Monte Carlo sittings — ability uncertainty plus 100-item sampling noise — are graded by the shared PRC rule (weighted 70% average AND no subject under 50%). Reports the strict pass probability, the **conditional** probability (average met, a subject under the floor — the most common way a strong reviewer fails, which v1's single P(θ > 0) could not see), the projected GWA with an 80% interval, each subject's projected rating, and the subject where half an SD of improvement moves the pass probability most. Weak topics rank by **decayed BKT mastery × syllabus weight** over every topic with history (v1 read only the 20 most recently touched, by log-odds of hit rate), lifted for topics answered confidently wrong and flagged when the median answer exceeds 3 minutes. ~20ms per compute behind the 60s cache, using a precompiled grader held to identical output by a 5,000-case contract test. Older-model snapshots are recomputed. Topnotcher stays a labelled θ-cutoff estimate (it is a cohort rank) (`engine/forecast.js`, `services/referenceFormCache.js`, `forecastRoutes.js`, `ForecastSnapshot.subjectForecasts` — migration `20261002020000_forecast_subject_projection`)
- [x] **Shared numerics** — dependency-free math helpers backing the above (`engine/math.js`)
- [x] **Nightly/on-demand calibration** — recalibrates item difficulty parameters from live attempt data. Reads the response matrix by keyset pagination rather than loading every attempt into memory, and writes item parameters and abilities in transactional chunks so a crash cannot leave half the bank calibrated (`services/calibrationService.js`, `npm run calibrate`)
- [x] **Targeted drill (Smart Drill v2)** — a short adaptive drill on a weak topic. With no target it drills the weakest topics by **decayed BKT mastery × syllabus weight** (the forecast's ranking), split 50/30/20 across the top three; a named topic (`topicId`, or a legacy label) drills just that. Items are chosen like a CAT: by Fisher information at the learner's ability in that subject, from a window of ±1 around θ that widens only when the topic is thin, picked randomesque among the most informative so two drills differ; uncalibrated items are placed by their author rating on the θ scale. **Blind-spot mode** leads with the questions answered confidently wrong. Never serves a flagged item or one seen in the last 24h, and returns items **with their answers** — the old route stripped `answer`, so the client marked every drill MCQ wrong and flashcards revealed a blank; it also ranked by raw accuracy on the legacy subtopic string and did not exclude flagged questions. Launched from Recommended fixes (Targeted drill / Blind spot), any heatmap tile ("Drill Calculus"), Progress › Weak spots (Weak-spot / Blind-spot drill), the Today card and Practice's "Weak points" — whose custom scope used to fall through to a plain Mathematics library session (`engine/drill.js`, `routes/smartDrillRoutes.js`)
- [x] **Spaced repetition (SRS)** — server-authoritative SM-2, scheduled inside the telemetry write transaction from evidence every surface already records: a miss or a low-confidence answer starts a card, any later answer to that question moves it, and quality comes from correctness × confidence (a confident miss — a blind spot — scores 0 and returns soonest). Due dates fall on Manila midnights. One read + one bulk upsert per chunk, so a replayed batch never reschedules twice. Active Review shows **"N questions due for review"** (capped at 30 per session, overdue count, or when the next review falls due once the queue is clear) and runs the queue as a normal session. Previously dead end to end: the client SM-2 hook was imported nowhere, `POST /srs/review` trusted client-computed intervals and had no callers, so no card was ever written and `/due` was always empty — the hook, that route, `/stats` and its schema are deleted (`engine/srs.js`, `services/telemetryService.js`, `routes/srsRoutes.js` `GET /due` + `GET /summary`, `hooks/useSrsSummary.js`, `features/active-recall/ReviewSetup.jsx`)

Its rules are unit-tested against synthetic credentials, because "matches nothing" and "regex is broken" are indistinguishable on a clean tree (`scripts/audit-{route-auth,sql-interpolation,secrets}.js`, `tests/auditSecrets.test.js`)
